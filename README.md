# API Трекера полезных привычек (Docker & CI/CD Edition) 🚀

Дипломный/курсовой проект бэкэнд-системы для отслеживания полезных привычек с автоматическим контролем бизнес-логики, фоновыми задачами Celery и контейнеризацией через Docker. Настроен автоматический CI/CD конвейер деплоя в Yandex Cloud.

---

## 🛠️ Технологический стек проекта
* **Язык разработки:** Python 3.11+
* **Фреймворк:** Django 5.0+ / Django REST Framework (DRF)
* **База данных:** PostgreSQL 15 (вместо SQLite)
* **Аутентификация:** JWT через `djangorestframework-simplejwt`
* **Фоновые задачи:** Celery
* **Брокер сообщений / Кэш:** Redis 7
* **Веб-сервер / Прокси:** Nginx (слушает стандартный порт 80)
* **Оркестрация:** Docker / Docker Compose
* **CI/CD & DevOps:** GitHub Actions ➡️ Автодеплой по SSH на ВМ в **Yandex Cloud**

---

## 🌐 Основные эндпоинты проекта

После сборки контейнеров проект доступен локально через Nginx на стандартном веб-порту `80`:
* **Главная страница с веб-интерфейсом:** `http://localhost/`
* **Интерактивная документация Swagger UI:** `http://localhost/api/docs/swagger/`
* **Строгая спецификация ReDoc:** `http://localhost/api/docs/redoc/`
* **Панель администратора Django:** `http://localhost/admin/`

### Набор эндпоинтов (Routing):
1. **Пользователи (`/api/users/`):**
   * `POST /register/` — Регистрация нового пользователя (авторизация по `email`).
   * `POST /login/` — Получение пары JWT-токенов (`access`, `refresh`).
   * `POST /token/refresh/` — Обновление истекшего `access`-токена.
2. **Привычки (`/api/habits/`):**
   * `GET /` — Просмотр списка личных привычек текущего пользователя (с пагинацией по 5 элементов).
   * `POST /` — Создание новой привычки (автоматическая привязка к `request.user`).
   * `GET /{id}/`, `PUT /{id}/`, `PATCH /{id}/`, `DELETE /{id}/` — CRUD-операции над конкретной привычкой.
   * `GET /public/` — Список всех публичных привычек системы для авторизованных пользователей (только чтение).

## 🧠 Реализованная бизнес-логика (Валидаторы)
В проекте реализованы жесткие кастомные валидаторы DRF на уровне `HabitSerializer`:
1. **Исключение одновременного выбора:** Нельзя одновременно заполнить поле вознаграждения (`reward`) и связанной привычки (`related_habit`).
2. **Ограничение по времени:** Время выполнения привычки (`duration_seconds`) должно быть не больше 120 секунд.
3. **Фильтрация связанных привычек:** В связанные привычки могут попадать только те записи, у которых флаг приятной привычки установлен в `is_pleasant=True`.
4. **Ограничения приятной привычки:** У приятной привычки не может быть вознаграждения или связанной привычки.
5. **Ограничение периодичности:** Привычку нельзя выполнять реже, чем 1 раз в 7 дней (значение поля `periodicity_days` не может быть больше 7).

## 🐳 Инструкция по запуску всей архитектуры в Docker

Благодаря контейнеризации вам больше не нужно запускать Redis, Celery и Django в разных терминалах вручную. Вся экосистема поднимается одной командой.

1. Заполните ваш файл конфигурации окружения **`.env`** в корне проекта на основе шаблона `.env.template`.
2. В терминале корневой папки проекта выполните команду сборки и запуска:
   ```bash
   docker compose up --build
   ```
3. Контейнеры автоматически скачают образы, соберут статику, применят миграции к PostgreSQL и запустят фоновые службы Celery Worker и Beat. Чтобы остановить проект, нажмите `Ctrl + C`.

## 🚀 Автоматизация CI/CD (GitHub Actions & Yandex Cloud)

В папке `.github/workflows/deploy.yaml` настроен автоматический пайплайн:
1. При каждом `git push` или `pull_request` в ветки `main`/`develop` GitHub разворачивает тестовое окружение и запускает проверку кода линтером (`flake8`) и автотестами.
2. При успешном прохождении тестов GitHub безопасно подключается по SSH к виртуальной машине в **Yandex Cloud**, подтягивает свежий код и перезапускает Docker-контейнеры в фоновом режиме (`-d`).
